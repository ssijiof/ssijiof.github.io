SQL语法

备注：

数据库连接（pymysql）
  • pymysql.connect(host, port, user, password, database, charset, cursorclass)：建立与 MySQL 的 TCP 连接，返回连接对象
  • charset="utf8mb4"：Python 与 MySQL 之间传输字符串时使用的编码
  • cursorclass=pymysql.cursors.DictCursor：指定查询结果以字典形式返回，可用键值对访问
  • conn.cursor()：创建游标对象，所有 SQL 语句通过 cursor 执行
  • conn.commit()：提交事务，将前面的操作真正写入数据库
  • conn.close()：断开连接
库和表操作
  • CREATE DATABASE IF NOT EXISTS 库名 CHARACTER SET utf8mb4：建库（如库已存在则跳过）
  • CREATE TABLE IF NOT EXISTS 表名 (...)：建表（如表已存在则跳过）
  • AUTO_INCREMENT：自增整数，通常用于主键
  • PRIMARY KEY：主键约束，唯一标识一行，相当于数组下标
  • FOREIGN KEY (当前表中要被约束的列) REFERENCES 外表(外表列)：外键约束，保证引用完整性——外键值必须在被引用表中存在
  • NOT NULL：非空约束
  • UNIQUE：唯一约束，不允许重复值
  • DEFAULT 值：默认值
  • 表之间相互独立，通过外键建立关联

语法规则
  • 占位符 vs f-string：
    • cursor.execute("... %s ...", (值,))：用占位符传值，PyMySQL 自动转义，防止 SQL 注入——用户输入只被当作数据，不会被当作 SQL 命令执行
    • f"... {变量} ..."：直接拼接字符串，如果变量来自用户输入，可能被注入恶意 SQL（如 '; DELETE FROM users; --）
    • 建库/建表用 f-string（无用户输入），插入/更新/条件查询用占位符（含用户输入）
  • SQL 关键字大小写均可（SELECT = select），但关键字通常大写便于区分
  • 字符串用单引号：'value'
  • 每条 SQL 语句以分号结尾（在 cursor.execute() 中可省略）
  • -- 开头为单行注释
  • DEFAULT CURRENT_TIMESTAMP：插入新行时自动填入当前日期时间（如 2026-08-04 10:52:50），常用于 created_at 等”创建时间”字段
  • f"CREATE DATABASE {DB_NAME}"：Python 的 f-string，{} 内是变量名，执行时替换为实际值
  • 三引号 """..."""：多行字符串，建表语句跨多行时用
  • with conn.cursor() as cursor:：上下文管理器，代码块结束后自动关闭 cursor（不论是否报错）
  • 连接数据库时可不指定 database 参数，用于先建库再连库的场景
fetchone() 和 fetchall()

1. 两个方法的对比

方法 返回类型 没数据时 适用场景
fetchone() 字典 {...} None 查单条（WHERE id = 1、WHERE username = ‘…’）
fetchall() 列表 [{...}, {...}] []（空列表） 查多条（可能有多行结果，不管有没有 WHERE）

2. fetchone() — 取一行

3. fetchall() — 取全部

4. 原理：cursor 内部有一根指针

一次 fetchone() 只会移动一次指针，取一条。fetchall() 等于不断调用 fetchone() 直到末尾，把取到的所有行装进一个列表返回。

5. 如何选择

选择的依据是结果有多少行，和 WHERE 无关——有 WHERE 的结果也可能多行。

  • SELECT ... WHERE 主键 = xxx → 结果最多 1 行 → 用 fetchone()
  • SELECT ... WHERE 外键 = xxx → 可能多条 → 用 fetchall()
  • SELECT * FROM 表 → 全表数据 → 用 fetchall()

TRUNCATE TABLE（清空表）

1. 语法

2. 作用

一次性删掉表内所有行，但保留表结构——列定义、约束、索引都还在，之后还能继续往里插数据。相当于把书里的内容撕光，书壳留着。

和 DELETE 最大的区别：TRUNCATE 不能加 WHERE，只能整表清空。想只删一部分行，只能用 DELETE ... WHERE。

3. 各关键字

部分 含义
TRUNCATE 清空操作，属于 DDL（数据定义语言），不是 DML
TABLE 固定写法，MySQL 中可省略（TRUNCATE employee 也能跑）
表名 要清空的表

4. 三个删除操作的完整对比

维度 DELETE TRUNCATE DROP
语句类型 DML（数据操作） DDL（数据定义） DDL
删除对象 满足 WHERE 的行 表内全部行 表本身：数据 + 结构 + 索引 + 约束
能加 WHERE 能 不能 —
表结构 保留 保留 一起删掉
自增计数器 不重置 重置为 1 —
能否回滚 能（事务内） 不能，隐式提交 不能，隐式提交
触发器 逐行触发 DELETE 触发器 不触发 不触发
执行速度 慢：逐行删除并写日志 快：直接删数据页重建 快
磁盘空间 不释放，留空洞（需 OPTIMIZE TABLE 回收） 释放，文件缩回初始大小 释放
所需权限 DELETE DROP DROP
外键引用 受约束规则限制（见「外键约束」一节） 被引用时直接报错 被引用时直接报错
典型场景 删部分数据、保留历史记录 清空测试数据、重置表 废弃表

三句话记住：

  • 只想删一部分，或者要留删除痕迹 → DELETE
  • 要整张表清空、且不关心自增 id 是否从 1 开始 → TRUNCATE
  • 这张表以后不要了 → DROP TABLE

DELETE 慢是因为它把每一行的删除都记进日志，为的是可以 ROLLBACK；TRUNCATE 快是因为它不走行级删除，直接把整块数据页丢掉，代价就是没有后悔药。

5. 几个要点

  • 自增归零：TRUNCATE 后 AUTO_INCREMENT 重置，下一次插入的 id 从 1 开始；DELETE 不会，新数据接着原来的最大值往后排
  • 不可回滚：TRUNCATE 会隐式提交事务，执行前开的 conn.begin() 之类都白搭，误操作没法 ROLLBACK
    • 补充：PostgreSQL 里默认不重置自增，要写 TRUNCATE TABLE employee RESTART IDENTITY
  • 不触发触发器：DELETE 会逐行触发 TRIGGER，TRUNCATE 不会
  • 有外键引用会报错：如果别的表有 FOREIGN KEY 指向这张表，TRUNCATE 会直接失败（报 Cannot truncate a table referenced in a foreign key constraint）。要么先清空引用它的子表，要么临时 SET FOREIGN_KEY_CHECKS = 0（详见「外键约束」一节）
  • 权限要求不同：需要 DROP 权限（底层是删表重建），而不是 DELETE 权限
  • 数据无法恢复：没有备份就没有退路，生产库上执行前务必确认

6. Python 中执行

TRUNCATE 属于 DDL，MySQL 会隐式提交，conn.commit() 加不加都行，但统一写上不碍事。

2. 创建外键的前提条件

以下任一条不满足，CREATE TABLE / ALTER TABLE 直接报错：

  • 被引用的列必须是主键或 UNIQUE——外键必须能唯一定位到父表的一行，指向一个普通列没有意义
  • 两列的数据类型必须完全一致——INT 对 INT，不能一个 INT 一个 BIGINT（数量级不同也不行）
  • 字符串列时字符集和排序规则要一致——否则报 Referencing column and referenced column are incompatible
  • 两张表必须是同一个存储引擎——MySQL 里只有 InnoDB 支持外键，MyISAM 建了会被静默忽略
  • 外键列会自动创建索引——MySQL 自动加，不用自己写；但不要手动删掉这个索引，否则外键会失效
  • 表里已有数据时，现有数据必须已满足外键约束——否则加不上，得先修数据

3. 子表写入时的规则

  • 往子表 INSERT / UPDATE 外键列时，该值必须在父表被引用列中存在，否则报错
  • 外键列可以为 NULL，NULL 不参与约束检查——表示”暂时没有关联对象”，常用于可选关联

4. 父表被删 / 被改时的四种行为

删除或修改父表被引用的那一列时，MySQL 按建表时声明的动作处理：

动作 含义
RESTRICT（默认） 拒绝：父表还有子表引用时，不允许删 / 改，直接报错
NO ACTION 和 RESTRICT 等价（MySQL 中行为相同）
CASCADE 级联：删父行 → 子表相关行一起删；改父行主键 → 子表外键跟着改
SET NULL 置空：删父行 → 子表外键设为 NULL（该列必须允许 NULL）

⚠️ ON DELETE CASCADE 用起来省事，但很危险：删一个场馆会连带删掉它下面所有场地和预约记录，没有任何提示。业务系统里默认用 RESTRICT 更安全，级联删除尽量只在明确的”主从表”场景使用。

5. 常见外键报错

报错信息 原因 处理
Cannot add or update a child row 插入的子表数据，外键值在父表里不存在 先插父表，或检查 id 是否写错
Cannot delete or update a parent row 删父行时还有子行引用它 先删子行，或改用 UPDATE 改状态
Cannot truncate a table referenced in a foreign key constraint TRUNCATE 的表被别的表引用 先清空子表，或临时关外键检查
Referencing column and referenced column are incompatible 两列类型 / 字符集不一致 改成完全一致的类型定义

6. 临时关闭外键检查

  • 只对当前连接生效，不影响的别的会话
  • 关掉后可以插入”孤儿行”（外键指向不存在的父行），数据就脏了，之后 JOIN 会莫名少数据
  • 用完之后一定要开回来；生产库上不要随手关

7. 查看和删除外键

外键是 MySQL 自动命名的，格式是 表名_ibfk_N，所以要先 SHOW CREATE TABLE 查到真实名字。

8. 使用建议

  • 外键不是必须的：很多互联网项目为了性能和高并发，选择在应用层（Python 代码）保证引用完整性，数据库不加外键——加了外键每次写入都要额外检查父表并加锁
  • 教学 / 中小型系统：加外键，让数据库帮忙兜底数据一致性
  • 高并发大流量系统：不加外键，靠代码和定期巡检保证；但删数据前必须在代码里自己检查有没有引用
  • 一旦加了外键，删除操作会变得”处处受限”，这是它保护数据一致性的代价，设计表结构时就要想清楚
